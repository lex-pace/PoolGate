# 2026-08-30 工作日志

## FreeBuff Token Monitor 模型名不一致排查
- 现象：用户在 FreeBuff 选 `mimo-v2.5`，但 PoolGate Token Monitor 显示 `openai/gpt-5.6-luna`。
- 结论：**非 PoolGate 采集 bug**。根因在 FreeBuff 端。
  - PoolGate 侧 `src-tauri/src/token_monitor/collector/freebuff.rs:286` 直接取 `metrics_json.context.model`，无改写；`normalization.rs` 的 `alias_model` 仅处理 Claude 系列，无 mimo→gpt 别名。
  - 实测 FreeBuff DB（`~/.config/freebuff-desktop/projects/poolgate-bda66be3-67f7-4d3e-ad0b-26204bdff9ca/desktop-v2.db`）：`threads.model` 取值只有 deepseek/*、minimax/minimax-m3、openai/gpt-5.6-luna、NULL；**全库无 mimo-v2.5 字符串**；messages.context.model 123/128 行为 NULL（新版 FreeBuff 不写消息级 model）。
  - 4 个 `threads.model='openai/gpt-5.6-luna'` 的线程 project_path 全部指向 poolgate 工作区 → 即用户用 mimo 的会话，FreeBuff 把用户选择落库为 openai/gpt-5.6-luna（FreeBuff 后端把 mimo-v2.5 路由/映射到了 openai/gpt-5.6-luna）。
- 模型解析优先级（freebuff.rs:686-696）：本行 context.model > 同线程前序带 model 行继承 > threads.model/world_snapshot 兜底。
- 处置建议：若需 Token Monitor 显示 mimo-v2.5，应改 FreeBuff 落库（threads.model 写用户真实选择）而非 PoolGate；当前如实显示真实后端模型其实更准确。
